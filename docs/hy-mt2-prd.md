## 1. 产品概述

### 1.1 产品背景

Apple Silicon 的统一内存让 1.8B 级别的模型可以常驻在 Mac mini 上，但现成的部署方式通常默认使用 PyTorch 或容器，既拿不到 Metal 加速，也会把多个模型的依赖装进同一个环境。Hy-MT2 的 1.8B 4-bit 版本已经能在 MLX 上运行，缺的是一套可重复安装、可观测、接口稳定的运行时。

本 PRD 只定义 Hy-MT2 这一个模型。统一调度器和多模型共存是后续阶段，不在本期验收范围内。

### 1.2 第一性原则分析

回到用户在按下「翻译」那一刻真正需要的东西，是**一段可信的译文**，而不是模型文件、Python 环境或 API 文档。

必要条件：

1. 权重在本机，断网也能翻。
2. 服务能在一台 Mac 上装好并稳定运行。
3. 输入和输出有固定格式，程序能调用。
4. 不翻译时要让出内存，别把整机拖慢。
5. 出错时用户知道是原文太长、服务没起来，还是模型加载失败。

约束：

- 只支持 Apple Silicon 的 macOS，不覆盖 Intel Mac 和 Linux。
- 推理必须走 MLX，torch 只允许出现在音频编解码等必要环节。
- 单机单用户为主，不承诺多租户和水平扩展。
- 本期只支持一个模型实例，切换模型需要重启进程。

### 1.3 产品目标

| 编号 | 目标 | 度量方式 | 验收口径 |
| --- | --- | --- | --- |
| G1 | 一次脚本完成安装 | 全新克隆到 CLI 翻出第一句译文 | 不手工装依赖、不改代码；失败时脚本给出可执行的下一步 |
| G2 | 命令行和 API 结果一致 | 同一原文、同一参数分别走 CLI 和 API | 两次输出逐字一致，允许尾部空白差异 |
| G3 | 空闲后内存真的还回去 | 用 `mx.get_active_memory()` 和 `mx.get_cache_memory()` 记录加载前、峰值、卸载后三个点 | 卸载后两项指标相对加载前基线的增量不超过峰值增量的 10% |
| G4 | 接口兼容 OpenAI | 用 OpenAI 官方 SDK 调用 | 非流式和流式都能正常解析，无需改 SDK 代码 |
| G5 | 翻译质量不劣于参考实现 | 固定测试集，双人独立评分 | 200 条中英互译样本，准确性、流畅度、术语、完整性四项各 1~5 分，总分平均不低于 4/5，且不劣于参考部署同参数结果；评分细则随测试集一并提供 |
| G6 | 运行期不联网 | 抓包或在断网环境运行 | 安装完成后翻译、健康检查、Web UI 均无外发请求 |

### 1.4 系统范围

**本期包含**

- Hy-MT2-1.8B-4bit 权重下载与校验
- 独立 Python 环境创建
- 模型加载、生成、空闲卸载
- 命令行翻译
- OpenAI 兼容的 HTTP API
- 单页 Web UI
- 健康检查与日志
- 安装、启动、排障文档

**本期不包含**

- 7B、30B-A3B 和其他量化精度
- Ming-3.0-tts 与语音相关能力
- 多模型调度器、模型热切换
- 鉴权、计费、多租户、限流之外的配额管理
- 术语表、上下文记忆、批量文件翻译
- 逐 token 流式输出
- 微调、权重转换、量化
- Windows、Linux、Intel Mac

| 用例编号 | UC-04 |
| 参与者 | 下游应用 |
| 优先级 | 高 |
| 前置条件 | 服务已启动 |
| 后置条件 | 返回 OpenAI 格式的译文响应，模型保持加载状态 |

```json

  "messages": [
```

## 4. 交互设计

### 4.1 整体流程

```text
安装（一次性）
  setup_hy_mt2.sh
    ├─ 建 envs/hy-mt2
    ├─ 装依赖
    ├─ 下载 models/hy-mt2/4bit
    └─ 校验必需文件

使用
  ├─ CLI ── 加载 ── 生成 ── 输出 ── 退出
  └─ 服务 ── 启动（不加载）
              ├─ 请求 ── 加载（首次）── 生成 ── 响应
              ├─ 空闲到阈值 ── 卸载
              └─ 新请求 ── 重新加载
```

### 4.2 首次请求子流程

```text
请求到达
  │
  ├─ 请求体超过 1MB ──► 413（不解析正文）
  │
  ├─ 参数校验失败 ──► 400
  │
  ├─ 用启动时的 tokenizer 算输入长度，超上下文 ──► 400（不加载权重）
  │
  ├─ 队列已满 ──► 429
  │
  └─ 入队
        │
        ├─ 模型已加载 ──► 生成
        │
        └─ 模型未加载 ──► 加载 ──► 成功 ──► 生成
                              │
                              └─ 失败 ──► 503
```

### 4.3 状态机

```text
Unloaded ──首次请求──► Loading ──成功──► Ready ──请求──► Generating
   ▲                     │                 ▲                 │
   │                     │ 失败            │ 生成完成         │
   │                     ▼                 └─────────────────┘
   │                   Failed
   │
   └── Unloading ◄── 空闲达到阈值且无在途请求 ── Ready
```

| 状态 | 含义 | 允许的请求 | 退出条件 |
| --- | --- | --- | --- |
| Unloaded | 进程已启动，模型不在内存 | 接受，触发加载 | 加载开始 |
| Loading | 正在读权重 | 排队 | 成功或失败 |
| Ready | 可生成 | 接受 | 收到生成任务或卸载任务 |
| Generating | 正在推理 | 排队 | 生成完成或异常 |
| Unloading | 正在释放 | 排队 | 释放完成 |
| Failed | 加载失败，处于冷却期 | 冷却期内返回 503，冷却结束后接受 | 冷却结束，首个请求触发重试 |

### 4.4 非流式请求时序

```text
客户端              FastAPI 事件循环           推理 worker              MLX
  │ POST 请求            │                         │                    │
  │─────────────────────►│ 校验、入队               │                    │
  │                      │────────────────────────►│ 加载（首次）         │
  │                      │                         │───────────────────►│
  │                      │                         │ 生成                │
  │                      │◄────────────────────────│ 译文                │
  │◄─────────────────────│ 200 chat.completion     │                    │
```

### 4.5 空闲卸载时序

```text
空闲检查线程         推理 worker              共享状态
  │ 每轮读取             │                       │
  │─────────────────────►│ 有在途任务？           │
  │                      │──────────────────────►│
  │                      │◄──────────────────────│ 否，且空闲达到阈值
  │                      │ 解除引用、gc、清缓存   │
  │                      │──────────────────────►│ 状态改为 Unloaded
  │ 下一轮                │                       │
```

### 4.6 线程模型

```text
uvicorn 事件循环（单线程）
  ├─ 接收请求、参数校验、错误映射
  ├─ 静态文件与 Web UI
  ├─ 把生成任务放入队列（上限 8）
  └─ await 结果后组装响应

推理 worker（单线程，唯一持有模型）
  ├─ 加载、生成、卸载
  ├─ 同一时刻只处理一个生成任务
  └─ 与事件循环通过队列和 Future 通信

空闲检查线程
  └─ 到达阈值时向推理 worker 投递卸载任务
```

### 4.7 并发约束与竞态

| # | 场景 | 危害 | 规则 |
| --- | --- | --- | --- |
| 1 | 空闲卸载与在途生成重叠 | 生成中模型被释放，请求崩溃 | 卸载任务与生成任务同队列，队列为空且无在途时才卸载（BR-33、BR-49） |
| 2 | 多个请求同时到达 | 同时进 Metal，结果串线或内存翻倍 | 单 worker 串行（BR-41） |
| 3 | 请求风暴 | 队列无限增长，内存和延迟失控 | 队列上限 8，余量检查和入队原子完成，超出 429（BR-42、BR-50） |
| 4 | 客户端在排队时断开 | 无效任务占用生成时间 | 排队中的请求移出队列；已开始生成的走完并丢弃结果（BR-48） |
| 5 | 客户端在生成时断开 | 生成继续占用资源 | v1 不取消，完成后丢弃结果（BR-44） |
| 6 | 加载失败后连续重试 | 每次请求都触发一次加载 | 失败后冷却 5 秒，冷却期内共享同一个失败结果（BR-34、BR-53） |
| 7 | 进程收到 SIGTERM 时正在生成 | 结果丢失或进程卡住 | 停止接新请求，队列中的请求返回 503，在途任务最多等 30 秒（BR-45、BR-51） |
| 8 | 两个进程抢同一端口 | 后启动的失败 | 启动时报错，不自动换端口（BR-15） |
| 9 | 运行中修改权重目录 | 新旧权重混用 | 权重路径启动时固定，修改需重启（BR-12） |
| 10 | 加载期间查询健康状态 | 页面误显示「已就绪」 | `/health` 必须返回 `state=loading`，页面据此显示加载中（BR-27、BR-52） |

## 6. 非功能需求

### 6.1 性能

性能指标先定义口径，验收时填入实测值。测量必须记录芯片型号、统一内存大小、macOS 版本和量化精度。

| 指标 | 口径 | 验收要求 |
| --- | --- | --- |
| 冷加载耗时 | 从收到首个请求到模型可用 | 连续 3 次，波动不超过 20% |
| 首句延迟 | 50 字中文输入，非流式，从请求到完整响应 | 记录 P50/P95，作为后续版本对比基线 |
| 稳态延迟 | 模型已加载，同长度输入 | 记录 P50/P95，与首句延迟分开统计 |
| 峰值内存 | 生成过程中进程物理内存峰值 | 记录绝对值，并与模型文件大小对照 |
| 卸载回收率 | 卸载后 `mx.get_active_memory()` 和 `mx.get_cache_memory()` 相对加载前基线的增量 | 不超过加载峰值增量的 10% |
| 重载成功率 | 卸载后连续 5 次请求 | 5/5 成功 |
| 并发稳定性 | 20 个并发请求 | 全部成功或明确 429，无崩溃、无串线 |

### 6.2 兼容性

| 项目 | 要求 |
| --- | --- |
| 硬件 | Apple Silicon（M1 及以上），统一内存需满足实测峰值，基线记录在 `docs/benchmarks.md` |
| 系统 | macOS 14 及以上 |
| Python | 3.11，与依赖锁定一致 |
| 浏览器 | Safari、Chrome、Edge 最近两个大版本 |
| OpenAI SDK | Python SDK 1.x 的非流式和流式调用 |
| 不支持 | Intel Mac、Linux、Windows、Docker、多 GPU |

### 6.3 安全与隐私

- 默认只监听 `127.0.0.1`，局域网访问必须显式传 `--host 0.0.0.0`。
- v1 不提供鉴权，开放到局域网时启动日志必须打印风险提示。
- 请求体上限 1MB，超出返回 413，避免超大文本打满内存。
- 默认不启用 CORS，Web UI 与 API 同源；跨源调用不在本期支持范围。
- 不采集遥测，不调用外部服务，安装完成后运行期无外发请求。
- Web UI 不引用 CDN、外部字体或第三方脚本。
- 日志默认不记录原文、译文和完整请求体。
- 权重只从锁定来源下载并记录 revision，依赖版本锁定，避免供应链漂移。
- 安装后保留 `LICENSE.txt`，README 注明模型许可证和来源，不再分发权重。
- Web UI 不持久化原文和译文，刷新即清空。

### 6.4 可靠性

- 单个请求失败不影响进程，后续请求可继续。
- 模型加载失败后返回 503，允许重试，不需要重启进程。
- 健康检查不触发模型加载，不阻塞生成。
- 收到 SIGTERM 后停止接新请求，等待在途任务，30 秒后强制退出。
- 崩溃后不自动重启，由用户或外部进程管理器决定。

| 7 | 卸载与生成并发 | 100 次交替触发，无崩溃、无脏结果 |
| 8 | 队列上限行为 | 第 9 个排队请求返回 429，前 8 个正常 |
| 9 | 断网运行 | 安装完成后翻译、健康检查、UI 均可用 |
| 10 | 启动时只加载 tokenizer | `/health` 的 `model_loaded` 为 false，长度校验可用，内存无明显增长 |
| 11 | `/health` 状态流转 | 能依次观察到 `unloaded`、`loading`、`ready`、`generating`、`unloading` |
| 12 | 请求体上限 | 超过 1MB 返回 413，小请求不受影响 |

## 8. 业务规则汇总

| 编号 | 规则 |
| --- | --- |
| BR-01 | 环境固定放在 `envs/hy-mt2`，权重固定放在 `models/hy-mt2/4bit`，两者都不入库 |
| BR-02 | 安装脚本必须幂等，已存在的环境和权重不重复创建或下载 |
| BR-03 | 运行时使用 Python 3.11，依赖以 `runtimes/hy_mt2/requirements.txt` 为准 |
| BR-04 | 权重来源固定为 ModelScope `bujidc/mlx-community_Hy-MT2-1.8B-4bit`，下载时记录 revision；安装后运行期不得联网 |
| BR-05 | 安装完成前必须校验 `config.json`、至少一种分词器文件（`tokenizer.json` 或 `tokenizer.model`）、至少一个 `*.safetensors` 和 `.revision`，缺失则非零退出 |
| BR-06 | 卸载只删除 `envs/hy-mt2` 和 `models/hy-mt2/4bit`，不修改系统 Python |
| BR-07 | CLI 参数为 `--text`、`--target`、`--max-tokens`，`--target` 默认中文 |
| BR-08 | 翻译指令固定为 `Translate the following segment into {target}, without additional explanation:` 加两个换行和原文 |
| BR-09 | CLI 的标准输出只放译文，日志走标准错误 |
| BR-10 | CLI 退出码为 0 成功、2 参数错误、1 运行错误 |
| BR-11 | CLI 和 API 共用同一套模型管理和提示词构造逻辑，不允许两套实现 |
| BR-12 | 服务通过 `scripts/start_hy_mt2.sh` 启动，底层是 `runtimes.hy_mt2.app:create_app` 的 uvicorn factory；脚本只做环境和端口检查，不复制业务逻辑 |
| BR-13 | 只允许单 worker，禁止 `--workers` 大于 1 |
| BR-14 | 服务启动时只加载 tokenizer 和对话模板，不加载权重，`/health` 立即可用 |
| BR-15 | 端口被占用时启动失败并明确报错，不自动换端口 |
| BR-16 | `POST /v1/chat/completions` 的 `messages` 必填且至少一条 |
| BR-17 | 源语言由模型自动判断，v1 不提供源语言字段；目标语言由调用方写在最后一条 user 消息里，服务端不改写消息内容 |
| BR-18 | 非流式响应字段固定为 `id`、`object`、`created`、`model`、`choices`；`finish_reason` 正常结束为 `stop`，达到 `max_tokens` 为 `length`；v1 不返回 `usage` |
| BR-19 | 生成参数默认值和范围按 UC-04 的请求数据表执行，越界返回 400 |
| BR-20 | `model` 字段宽松接受，响应原样回显，服务端只服务当前已配置模型 |
| BR-21 | 未识别的请求字段忽略，不因为 OpenAI 客户端多传字段而报错 |
| BR-22 | 服务启动时加载 tokenizer；校验阶段用 tokenizer 计算 `messages` 的 token 数，加上 `max_tokens` 不得超过上下文。上限取 `config.json` 的 `max_position_embeddings`，缺失时取 tokenizer 的 `model_max_length`，都不可用则记录警告并跳过长度校验。超限返回 400，不加载权重 |
| BR-23 | `stream=true` 时返回 `text/event-stream`，每块以 `data: ` 开头、空行结尾 |
| BR-24 | v1 的流式是整段生成后分块下发，不是逐 token 生成，文档必须如实说明 |
| BR-25 | 流式结束必须下发 `finish_reason=stop` 或 `length` 的空 delta，以及 `data: [DONE]` |
| BR-26 | `/v1/models` 固定返回一个条目，`id` 为 `Hy-MT2` |
| BR-27 | `/health` 返回 `status`、`state`、`model_loaded`、`idle_seconds`、`idle_timeout_seconds`，失败时附带 `last_error`；`state` 取值为 `unloaded`、`loading`、`ready`、`generating`、`unloading`、`failed`；不暴露绝对路径 |
| BR-28 | `/health` 和 `/v1/models` 不得触发模型加载 |
| BR-29 | 模型在第一次生成请求时加载，加载过程对同一请求可见 |
| BR-30 | `idle_timeout` 默认 1200 秒，`0` 表示常驻，负数启动即失败并给出配置错误 |
| BR-31 | 空闲计时以最后一次生成完成时间为起点 |
| BR-32 | 卸载顺序为解除权重引用、`gc.collect()`、`mx.clear_cache()`，tokenizer 保留常驻 |
| BR-33 | 有在途生成或等待队列非空时不得卸载，卸载任务与生成任务在同一队列串行 |
| BR-34 | 加载失败后进入 5 秒冷却，冷却期内所有请求共享同一失败结果并返回 503，`state=failed`；冷却结束允许重试 |
| BR-35 | Web UI 为单页，包含原文输入、目标语言选择、翻译按钮、译文区和复制按钮 |
| BR-36 | Web UI 默认目标语言为中文，语言列表见附录 A-5 |
| BR-37 | 请求期间禁用翻译按钮并展示加载状态，禁止重复提交 |
| BR-38 | Web UI 的错误提示使用中文，不展示堆栈、路径和内部类型名 |
| BR-39 | Web UI 不持久化原文和译文，不埋点，不读取本地文件 |
| BR-40 | Web UI 与 API 同源同端口，入口路径为 `/` |
| BR-41 | 同一时刻只允许一个生成任务，其余请求排队 |
| BR-42 | 等待队列上限默认 8，不含在途任务，可通过 `HY_MT2_MAX_QUEUE` 调整；余量检查和入队在同一把锁内完成，超出返回 429 并带 `Retry-After` |
| BR-43 | 所有错误响应统一为 `{"error": {"type": "...", "message": "..."}}`，含 413、404、405 和 FastAPI 默认 422 的映射；流式场景以 `data: {json}` 下发后关闭连接 |
| BR-44 | 客户端断开后 v1 不取消生成，完成后丢弃结果 |
| BR-45 | 收到 SIGTERM 后停止接新请求，等待在途完成，30 秒后强制退出 |
| BR-46 | info 级日志不得记录原文、译文和完整请求体；调试日志通过 `HY_MT2_LOG_LEVEL=DEBUG` 显式开启 |
| BR-47 | 默认监听 `127.0.0.1`，开放局域网必须显式指定 host，并在启动日志提示无鉴权风险 |
| BR-48 | 排队中的请求在客户端断开后立即移出队列，不进入生成；已开始生成的请求按 BR-44 处理 |
| BR-49 | 卸载必须同时满足权重已加载、等待队列为空、无在途生成、空闲达到阈值，四项缺一不可 |
| BR-50 | 队列余量检查与入队在同一把锁内完成，入队失败直接返回 429，禁止先入队再检查 |
| BR-51 | 收到 SIGTERM 后，等待队列中的请求立即返回 503，`error.type` 为 `model_unavailable`，不再进入生成 |
| BR-52 | `state` 的取值和转换以 4.3 状态机为准，`/health`、日志和 Web UI 使用同一套状态名 |
| BR-53 | 冷却期内的请求共享同一次失败结果，不得各自触发加载；冷却结束后由第一个请求负责重试 |
| BR-54 | 达到 `max_tokens` 时，非流式和流式的 `finish_reason` 均为 `length`，不得下发 `stop` |
| BR-55 | 请求体上限 1MB，超出返回 413 且不解析正文；上限不提供环境变量放开 |
| BR-56 | 安装后保留 `LICENSE.txt`，README 注明模型许可证和来源，权重不进入 git |
| BR-57 | 已存在权重的 `.revision` 与锁定 revision 不一致时，安装脚本重新下载，不静默复用 |

## 9. 易用性设计原则

### 9.1 零配置开始

用户只需要一条命令完成安装，第二条命令开始翻译。模型路径、端口、空闲阈值都有默认值，不要求先读文档。

### 9.2 用户可见配置不超过 4 项

| 配置 | 是否常驻界面 | 说明 |
| --- | --- | --- |
| 目标语言 | 是 | 每次翻译都可能变化 |
| 最大生成长度 | 否，高级设置 | 默认值覆盖大多数场景 |
| 空闲阈值 | 否，环境变量 | 部署时设定一次 |
| 监听地址和端口 | 否，启动参数 | 部署时设定一次 |

### 9.3 不主动打扰

- 不在页面弹订阅、评分、更新提示。
- 模型加载和卸载只在状态徽标上体现，不弹窗。
- 错误只展示一条可行动的信息，不堆叠技术细节。

### 9.4 小白语言规范

| 内部说法 | 面向用户说法 |
| --- | --- |
| 模型未加载 | 正在准备翻译模型，稍等一下 |
| 队列已满 | 当前请求太多，请稍后重试 |
| 输入超出上下文 | 原文太长，请分段翻译 |
| 权重缺失 | 没有找到翻译模型，请先运行安装脚本 |
| SSE / 流式 | 译文会分块显示 |
| 503 / 500 | 服务暂时不可用，请查看日志 |

### 9.5 状态表达简化

| 内部状态 | 页面文案 |
| --- | --- |
| Unloaded | 已就绪 |
| Loading | 正在准备模型 |
| Ready | 已就绪 |
| Generating | 正在翻译 |
| Unloading | 正在释放内存 |
| Failed | 模型加载失败 |
