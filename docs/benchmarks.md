### 1.5 停止头异常（§6.5-13）

14 次合成中观测到 1 次异常：`voice_design` 一条 12 词英文请求生成 26.40 s 音频，接近 512-position 缓存上限（约 30 s），随后同参数重跑 3 次均为 1.30 - 3.44 s。与模型 README 所述「stop head 偶尔不触发」一致。

| 观测项 | 值 |
| --- | --- |
| 复现次数 / 总次数 | 1 / 14 |
| 规避方式 | 换 seed 重试（PRD BR-96 的前端提示依赖此项） |

### 1.6 T-06 内置音色枚举（§6.5-5）

结论：**mlx-audio 0.6.1 不暴露 Ming-3.0 内置音色清单**。`bailingmm.py` 只有正则 `^(?:(?:US|UK)_[A-Z][a-z]+|[\u4e00-\u9fff][\u4e00-\u9fff_]*)$`，任何形如 `US_James`、`UK_Charlotte` 或纯中文名的字符串都会被当作 IP caption 透传，未知音色不会在模型层报错。

- 已知可用示例（模型 README）：`US_James`、`US_Emma`、`UK_George`、`UK_Charlotte`、`US_Stella`、`灵小柔`。
- v1 处理：UI 保持自由输入组合框加示例；API 只能校验命名形式，无法判定「名字合法但不存在」，`docs/api.md` 必须写明这一点。

### 1.9 T-09 seed 与内联标签（§6.5-11/13/14）

**seed**：mlx-audio 0.6.1 的 `generate()` 没有 seed 参数，采样噪声来自全局 `mx.random`。实测在生成前调用 `mx.random.seed(42)`，同一文本连续两次输出**逐字节相同**；换 seed 7 后结果不同（最大差值 0.70）。因此 seed 可由 worker 在串行执行时设置，前提是单 worker，不得并发调用。

**内联标签**：14 种标签均原样进入模型并完成合成，无抛错、无过滤：

| 标签 | 音频(s) | 标签 | 音频(s) |

| `[Breathing]` | 1.36 | `[Confirmation-en]` | 1.92 |
| `[Cough]` | 2.00 | `[Question-ei]` | 1.68 |
| `[Sigh]` | 2.00 | `[Question-ah]` | 2.24 |
| `[Laughter]` | 2.48 | `[Question-en]` | 1.20 |
| `[Surprise-ah]` | 1.84 | `[Question-oh]` | 1.84 |

## 2. 性能与内存

按 §6.1.1 协议采集。测试时浏览器页面关闭，机器未接电源以外的其他负载；每项预热 1 次后连续 5 轮，分位数为 nearest-rank，保留全部原始值。

采集命令：

```bash
envs/ming-tts/bin/python scripts/bench_ming_tts.py --mode all --rounds 5 > /tmp/ming_bench.json
```

内存项由脚本拉起独立子进程，基线为进程启动、加载 tokenizer、连续空闲 60 秒后的采样；合成期间 1 Hz 采样；卸载完成后按 0/5/30/60 秒采样。

> 本节机型是 Apple M2 16GB，不是 §6.1 的验收基准机 M4 Pro 24GB。数值只代表本机，不外推到其他 Apple Silicon。

### 2.1 加载与首请求耗时

| 指标 | 原始值(s) | P50 | P95 | 最小 | 最大 |
| --- | --- | --- | --- | --- | --- |
| 模型加载 | 1.335 / 1.059 / 1.190 / 1.053 / 0.991 | 1.059 | 1.335 | 0.991 | 1.335 |

### 2.3 内存

基线：进程启动 + tokenizer 校验 + 空闲 60 秒，RSS 59.7MB，MLX active/cache 均为 0。

| 阶段 | RSS(MB) | MLX active(MB) | MLX cache(MB) |
| --- | --- | --- | --- |
| 基线 | 59.7 | 0.0 | 0.0 |
| 峰值 | 297.8 | 1517.2 | 337.8 |
| 卸载后 0 秒 | 170.5 | 0.0 | 0.0 |
| 卸载后 5 秒 | 170.6 | 0.0 | 0.0 |
| 卸载后 30 秒 | 170.6 | 0.0 | 0.0 |
| 卸载后 60 秒 | 158.1 | 0.0 | 0.0 |

判定：

- 权重引用已释放：卸载后 MLX active 为 0，相对基线的增量为 0，满足「≤ 峰值增量的 10%」。
- MLX 缓存已清空：卸载后 cache 为 0。
- 进程 RSS 已回落：60 秒时 158.1MB，低于基线 + max(200MB, 峰值增量 × 20%) = 59.7 + max(200, 47.6) = 259.7MB。
- 峰值 active 1517.2MB 与 1.57GB 权重文件大小相当，没有低于权重体积。

修复前的对照：同一脚本首次运行时，卸载后 `active` 仍为 1507.4MB，RSS 也停在 328MB 左右。根因是 mlx-audio 的 `bailingmm` 包把可选的 `onnx` 导入异常保存在模块全局，异常的 traceback 固定首次导入时的栈帧，权重字典被间接持有。修复方式是在 `model_manager.py` 模块导入阶段先触发一次该导入，详见 [T-47 结论](ming3-tts-tasks.md)。
