## 1. 产品概述

### 1.1 产品背景

MlxForge 的第一个模型 Hy-MT2 已经跑通，验证了「独立 venv + MLX 推理 + OpenAI 兼容接口 + 单页 Web UI + 空闲卸载」这套骨架。第二个模型选 Ming-3.0-tts-0.5B：它只有 0.5B 参数，MLX 8-bit 转换版权重约 1.5GB，能在统一内存里常驻，同时提供内置音色、零样本克隆、声音设计、多语言和方言等能力，适合作为本地语音合成运行时。

Ming-3.0-tts 的官方推理实现是 PyTorch，MLX 转换版需要搭配 mlx-audio 使用。mlx-audio 0.6.0 及更早版本虽然能加载模型，但缺少 prompt 契约修复，会出现「念错词」；必须使用包含 PR #1047 的版本。这是本 PRD 把依赖版本写死的原因。

8-bit 权重已由本项目维护者上传到 ModelScope 的 `bujidc/mlx-community_Ming-3.0-tts-0.5B-8bit`，安装脚本默认从该仓库下载；原始转换版仍在 Hugging Face 的 `mlx-community/Ming-3.0-tts-0.5B-8bit`，作为备用来源。

本 PRD 只定义 Ming-3.0-tts 这一个模型。统一调度器和多模型共存仍是后续阶段，不在本期验收范围内。

### 1.2 第一性原则分析

回到用户按下「生成语音」那一刻真正需要的东西，是**一段能直接播放、听起来像目标声音的音频**，而不是模型文件、Python 环境或参数文档。

必要条件：

1. 权重和推理都在本机，断网也能合成。
2. 服务能在一台 Mac 上装好并稳定运行，不需要 NVIDIA 显卡。
3. 输入文本和输出音频有固定格式，程序能调用。
4. 不合成时要让出内存，别把整机拖慢。
5. 内置音色、克隆、声音设计三条路径都能走通，且不会静默忽略用户设置的参数。
6. 出错时用户知道是文本太长、参考音频不合格、服务没起来，还是模型加载失败。
7. 声音克隆涉及他人声音，界面必须明确授权责任；参考音频不持久化、不外传，处理结束立即删除临时文件。

约束：

- 只支持 Apple Silicon 的 macOS，不覆盖 Intel Mac 和 Linux。
- 推理走 MLX，不把 PyTorch 当推理后端；音频编解码使用 MLX 侧实现或标准库。
- 复用 mlx-audio 的模型加载和生成，不自己写权重解析、声学循环和声码器。
- 单机单用户为主，不承诺多租户和水平扩展。
- 本期只支持一个模型实例，切换模型需要重启进程。
- 不与 Hy-MT2 互相 import；跨模型共用逻辑等 `server/` 落地后再抽取。

### 1.3 产品目标

| 编号 | 目标 | 度量方式 | 验收口径 |
| --- | --- | --- | --- |
| G1 | 一次脚本完成安装 | 全新克隆到 CLI 生成第一段语音 | 不手工装依赖、不改代码；失败时脚本给出可执行的下一步 |
| G2 | 命令行和 API 结果一致 | 同一文本、同一参数、同一 seed 分别走 CLI 和 API | 音频时长差异不超过 0.2 秒，人工听感一致；不做逐字节比较 |
| G3 | 空闲后内存真的还回去 | 同时记录 `mx.get_active_memory()`、`mx.get_cache_memory()` 和进程 RSS，覆盖加载前、峰值、卸载后 0/5/30/60 秒 | MLX 侧缓存增量不超过峰值增量的 10%；进程 RSS 在卸载后 60 秒不超过基线 + max(200MB, 峰值增量的 20%)；峰值增量为 0 时只按绝对增量判断 |
| G4 | 接口兼容 OpenAI 非流式子集 | 用 OpenAI Python SDK 的 `audio.speech.create`，显式指定 `voice` 和 `response_format` 调用 | 能拿到音频二进制并保存为可播放 WAV；字段差异按 §6.2 兼容矩阵逐项验收 |
| G5 | 合成质量不劣于参考实现 | 固定 50 条文本，双人独立评分 | 可懂度、自然度、音色一致性、指令遵循四项各 1~5 分，总分平均不低于 4/5，且不劣于 mlx-audio CLI 同参数结果；评分细则和失败样本上限见 §6.1.2 |
| G6 | 运行期不联网 | 安装阶段允许联网；运行阶段抓包或断网验证 | 首次加载、失败重试、健康检查、Web UI、音频播放和下载均无外发请求 |
| G7 | 参数不被静默忽略 | 构造互斥参数组合逐条验证 | 所有冲突组合返回 400 并说明原因，不出现「传了但没生效」 |
| G8 | 能力承诺可追溯 | 每个能力标记为「转换方已验证」「待 Spike」或「暂不承诺」 | 未通过 Spike 的能力不在 Web UI 暴露；API 文档同步标注实验状态 |

### 1.4 系统范围

**本期包含**

- Ming-3.0-tts-0.5B-8bit 权重下载与校验
- 独立 Python 环境创建，mlx-audio 固定到包含 PR #1047 的提交
- 模型加载、合成、空闲卸载
- 命令行合成
- OpenAI Audio Speech 非流式兼容子集：`POST /v1/audio/speech`
- 内置音色、零样本声音克隆、声音设计、自由指令（能力状态见 §1.7）
- 中文、英语、德语、西班牙语、法语、韩语、日语（能力状态见 §1.7）
- 四川话、粤语方言（待 Spike，未通过前不在 UI 暴露）
- 情绪、语速、音高、音量控制（待 Spike，未通过前不在 UI 暴露）
- 14 种内联副语言标签透传（仅示例标签确定，其余待 Spike）
- WAV、PCM 输出
- 单页 Web UI
- 健康检查与日志
- 安装、启动、排障文档

**本期不包含**

- bf16、4-bit、fp16 和其他量化精度
- Ming-3.0-tts-tiny
- 流式音频、SSE 推流、边生成边播放
- MP3、Opus、AAC、FLAC 输出
- 浏览器录音与音频格式转换
- 参考音频持久化、音色库、音色管理
- 声音设计叠加参考音频（v1 声音设计只接受文字描述）
- 多人对话、播客脚本、背景音乐
- 语音识别与音频理解
- 多模型调度器、模型热切换
- 鉴权、计费、多租户
- 微调、权重转换、量化
- Windows、Linux、Intel Mac、Docker

| 能力 | 状态 | 依据 | v1 处理 |

| 声音设计 | 转换方已验证 | 模型卡示例 | 开放 |
| 自由指令 | 转换方已验证 | 模型卡示例 | 开放 |
| 内置音色完整枚举 | 部分已验证 | 公开示例只有 `UK_Charlotte` | 开放自由输入，不内置完整枚举 |
| 14 种内联副语言标签 | 部分已验证 | 官方只给出 `[Sigh]`、`[Cough]` 示例 | 原样透传，UI 只提示这两个示例 |
| 情绪控制 | 待 Spike | MLX 转换版未使用 CAM++，情绪任务是否成立未验证 | 不在 UI 暴露；API 接受但标注实验 |

| 四川话、粤语方言 | 待 Spike | 依赖 CAM++ 与方言任务 | 不在 UI 暴露；API 接受但标注实验 |
| IP 角色 | 待 Spike | 只在官方 cookbook 出现，缺可复现示例 | 不在 UI 暴露；API 接受但标注实验 |

**能力状态与 API 行为必须一一对应**

| 能力状态 | API 行为 | 文档与 UI |
| --- | --- | --- |
| 已验证并开放 | 正常接受，效果作为承诺范围 | UI 暴露，`docs/api.md` 正常描述 |
| 待 Spike、允许实验 | 接受参数并原样传入模型；不承诺效果，可能不生效；可检测的失败返回 400 并说明字段，不可检测时不得声称已生效 | UI 不暴露；`docs/api.md` 标注「实验」，并写明「参数可能不产生预期效果」 |
| Spike 判定模型不支持 | 返回 400 `invalid_request_error`，`message` 指出不支持的字段 | UI 不暴露；`docs/api.md` 标注「不支持」 |
| 尚未开放、禁止调用 | 返回 400，不进入推理 | UI 不暴露；`docs/api.md` 标注「未开放」 |

> 「实验」的含义是参数会被传入且不被服务端丢弃，但效果不保证；这与 BR-32 的「不得静默忽略」不冲突：BR-32 约束的是已承诺能力和明确的参数冲突，实验能力由本节单独定义。
>
> 状态只能依据 §6.5 的 Spike 结论变更，结论写入 `docs/benchmarks.md` 后才能改这张表（BR-83）。未通过 Spike 的能力不得出现在 Web UI（BR-82）。
>
> 单项能力之外，任务模式矩阵（A-6）允许的**组合**（如克隆 + 多语言、内置音色 + 显式 `multilingual`、指令 + 多语言）没有转换方验证依据，按 §6.5 第 32 项补验；验证结论写入 `docs/benchmarks.md` 前，Web UI 不主动引导这些组合。

### 4.3 任务模式解析

```text
请求到达
  │
  ├─ 归一化默认值：speed=1.0、pitch=0、volume=1.0、voice=auto、
  │  language 缺省/auto/zh/en 视为「未设置」；model/input/response_format/seed/cfg/sigma 不算控制项
  │
  ├─ 冲突检查（任一命中即 400，不进入解析，也不做静默降级）
  │    1. reference_audio 与 内置音色 或 voice=design 同时出现
  │    2. 内置音色 且 instructions 非空（voice=design 不适用本条）
  │    3. instructions 与 emotion 或属性非默认同时出现
  │    4. instructions 与方言语言同时出现
  │    5. emotion 或属性非默认 与方言语言同时出现
  │    6. reference_audio 与方言语言同时出现
  │    7. voice=design 与 emotion 或属性非默认同时出现
  │
  ├─ task 显式指定？── 是 ──► 按 A-6 校验必填项和禁止项 ──► 冲突 400
  │
  └─ 否（auto），按下表自上而下取第一条命中
        │
        ├─ 1. 有 reference_audio ──────────────► TTS（克隆）
        ├─ 2. voice=design ────────────────────► VOICE_DESIGN
        ├─ 3. language=四川话/粤语 ────────────► DIALECT
        ├─ 4. 有 emotion 或属性非默认 ─────────► EMOTION（可带 5 种语言 ID）
        ├─ 5. 有 instructions ─────────────────► FREEFORM（可带 5 种语言 ID）
        ├─ 6. voice 为内置音色 ────────────────► TTS（内置音色）
        ├─ 7. language=de/es/fr/ko/ja ─────────► MULTILINGUAL
        └─ 8. 其他 ────────────────────────────► BASIC
```

**易混淆组合的确定结果**

| 输入组合 | 解析结果 | 理由 |
| --- | --- | --- |
| `language=de` + `emotion=高兴` | `EMOTION`，language ID 传 `de` | 情绪命中的优先级高于多语言；情绪任务本身支持多语言 |
| `language=de` + `instructions` | `FREEFORM`，language ID 传 `de` | 自由指令命中优先于多语言 |
| `language=de` + 内置音色 | `TTS`，language ID 传 `de` | 内置音色优先于多语言 |
| `language=de` 单独出现 | `MULTILINGUAL` | 没有其他控制项，只差一个 language ID |
| `voice=design` + `instructions` | `VOICE_DESIGN` | `voice=design` 需要指令，不触发 BR-38 的「内置音色 + 指令」冲突 |
| `task=freeform` + `reference_audio` + `reference_text` | `FREEFORM`，跟随参考音色 | 官方明确自由指令可带参考音频；`auto` 不会推断出这一组合，必须显式指定 `task` |
| `reference_audio` + `language=sichuanese` | 400 | 克隆与方言是两条互斥路径 |
| 无任何控制项，`voice=auto`、`language=zh`、`seed=42` | `BASIC` | 三项都不是控制项 |

### 4.4 状态机

```text
Unloaded ──首次请求──► Loading ──成功──► Ready ──请求──► Generating
   ▲                     │                 ▲                 │
   │                     │ 失败            │ 合成完成         │
   │                     ▼                 └─────────────────┘
   │                   Failed
   │
   └── Unloading ◄── 空闲达到阈值且无在途请求 ── Ready
```

| 状态 | 含义 | 进入条件 | 允许操作 | 退出条件 | 异常恢复 |
| --- | --- | --- | --- | --- | --- |
| `unloaded` | 进程已启动，权重不在内存 | 进程启动完成；卸载成功 | 接受请求，首个请求触发加载 | 收到合成任务 → `loading` | — |
| `loading` | 正在读取权重 | 首个请求；冷却结束后的首个请求；卸载完成后的首个请求 | 新请求排队；`/health` 返回 `loading` | 加载成功 → `ready`；加载失败 → `failed` | 加载抛异常时释放半成品引用并 `gc.collect()`，写入 `last_error`，不残留部分权重 |
| `ready` | 权重在内存，可立即合成 | 加载成功；合成结束；卸载失败回退 | 接受请求；空闲检查可投递卸载任务 | 收到合成任务 → `generating`；空闲达阈值 → `unloading` | — |
| `generating` | 正在推理 | 从队列取出合成任务 | 新请求排队；`/health` 返回 `generating` | 合成完成或失败 → `ready` | 合成抛异常时丢弃结果、返回 500，状态回 `ready`，不触发卸载 |
| `unloading` | 正在释放权重 | 空闲达阈值，且队列为空、无在途任务 | 新请求排队，等待卸载后重新加载 | 释放完成 → `unloaded` | 释放抛异常时回到 `ready`，记录日志，下一轮再试，不把状态留在 `unloading` |
| `failed` | 加载失败，处于 5 秒冷却 | 加载失败 | 冷却期内所有请求直接 503；`/health` 返回 `failed` 和 `last_error` | 冷却结束后的首个请求 → `loading` | `last_error` 保留到下一次加载成功，冷却期从失败时刻起算 |

> `state` 只允许表中六个取值，实现不得增加未登记状态（BR-88）。`unloading` 期间到达的请求不改变状态，由 worker 在卸载完成后接着加载。

### 4.7 声音克隆数据流

参考音频的准确定位是**不持久化**：处理期间存在于内存和受权限保护的临时文件，请求结束立即删除；异常退出留下的文件在下次启动时清空。

```text
启动
  │ 安全创建 <系统临时目录>/ming-tts（0700），校验归属后清理本程序遗留文件
  ▼
客户端                FastAPI                推理 worker             临时目录（0700）
  │ base64 JSON         │                        │                      │
  │────────────────────►│ 校验大小、时长、格式     │                      │
  │                     │ 解码 base64（仅在内存）  │                      │
  │                     │ 写临时 WAV（0600）──────┼─────────────────────►│
  │                     │ 入队                    │                      │
  │                     │───────────────────────►│ 读取参考音频 + 文本     │
  │                     │                        │ 合成                  │
  │                     │◄───────────────────────│ 音频                  │
  │◄────────────────────│ 200 audio/wav           │                      │
  │                     │ finally 删除临时文件 ───┼─────────────────────►│
  ▼
进程退出
  │ 再次清空临时目录
```

| 环节 | 约束 |
| --- | --- |
| 目录位置 | `MING_TTS_TEMP_DIR`，默认 `<系统临时目录>/ming-tts`；不落在仓库和用户文档目录 |
| 安全创建 | 创建和检查时不跟随符号链接；`MING_TTS_TEMP_DIR` 解析后的真实路径必须等于预期路径，目录所有者必须是当前用户，权限过宽时收紧到 `0700` |
| 归属校验 | 目录内只允许存在本程序命名的文件（前缀固定），发现其他内容或路径指向目录外时不清理、不删除，按不安全处理 |
| 清理范围 | 只按固定前缀删除本程序创建的文件，不递归删除目录内容，不触碰目录之外的路径 |
| 降级策略 | 目录无法安全创建或无法确认归属时，禁用克隆功能：克隆请求返回 503，其他模式不受影响；不允许只记录日志后继续接受克隆请求 |
| 目录权限 | 启动时以 `0700` 创建，已存在则校验权限，过宽时收紧 |
| 文件权限 | 每个请求一个独立文件，权限 `0600`，文件名含请求标识 |
| 生命周期 | 校验阶段写入；删除权唯一归推理 worker：正常流程 worker 读取参考音频后删除，请求失败（含排队取消、排队超时、客户端断开）时由 handler 在确认请求未出队后于 `finally` 中删除，未出队判断与出队动作在同一临界区完成（BR-97） |
| 异常退出 | 崩溃或 `kill -9` 不会执行 `finally`，残留文件由下一次启动清空；系统重启也会清空临时目录 |
| 并发 | 每请求独立文件，不共用路径，避免并发克隆串线 |

### 4.8 线程模型

```text
uvicorn 事件循环（单线程）
  ├─ 接收请求、参数校验、任务解析、错误映射
  ├─ 静态文件与 Web UI
  ├─ base64 解码、参考音频解码与校验、临时文件写入、音频编码
  │   均在线程池执行，不阻塞事件循环（BR-98）
  ├─ 把合成任务放入队列（上限 8）
  └─ await 结果后组装响应

推理 worker（单线程，唯一持有模型）
  ├─ 加载、合成、卸载
  ├─ 同一时刻只处理一个合成任务
  └─ 与事件循环通过队列和 Future 通信

空闲检查线程
  └─ 到达阈值时向推理 worker 投递卸载任务
```

### 4.9 并发约束与竞态

| # | 场景 | 危害 | 规则 |
| --- | --- | --- | --- |
| 1 | 空闲卸载与在途合成重叠 | 合成中模型被释放，请求崩溃 | 卸载任务与合成任务同队列，队列为空且无在途时才卸载（BR-52、BR-53） |
| 2 | 多个请求同时到达 | 同时进 Metal，结果串线或内存翻倍 | 单 worker 串行（BR-56） |
| 3 | 请求风暴 | 队列无限增长，内存和延迟失控 | 等待队列上限 8（不含在途），余量检查和入队原子完成，第 9 个等待请求 429（BR-57、BR-87） |
| 4 | 排队超时与出队同时发生 | 请求被重复处理或状态错乱 | 出队与超时标记在同一把锁内完成，已出队的请求不再触发超时（BR-58） |
| 5 | 客户端在排队时断开 | 无效任务占用合成时间 | 排队中的请求移出队列；已开始合成的走完并丢弃结果（BR-59） |
| 6 | 客户端在合成时断开 | 合成继续占用资源 | v1 不取消，完成后丢弃结果（BR-59） |
| 7 | 加载失败后连续重试 | 每次请求都触发一次加载 | 失败后冷却 5 秒，冷却期内共享同一个失败结果（BR-54） |
| 8 | 进程收到 SIGTERM 时正在合成 | 结果丢失或进程卡住 | 停止接新请求，队列中的请求返回 503，在途任务最多等 120 秒（BR-60） |
| 9 | 两个进程抢同一端口 | 后启动的失败 | 启动时报错，不自动换端口（BR-15） |
| 10 | 运行中修改权重目录 | 新旧权重混用 | 权重路径启动时固定，修改需重启（BR-12） |
| 11 | 加载期间查询健康状态 | 页面误显示「已就绪」 | `/health` 必须返回 `state=loading`，页面据此显示加载中（BR-48） |
| 12 | 两个克隆请求共用临时文件 | 参考音频串线 | 每请求独立临时文件，处理完立即删除（BR-61、BR-85） |
| 13 | 卸载过程中到达新请求 | 请求被拒绝，或状态卡在 `unloading` | 请求排队，卸载完成后由 worker 重新加载，状态按 §4.4 转换（BR-88） |
| 14 | 服务关闭时排队请求的 Future 未完成 | 调用方一直等待，进程无法干净退出 | 关闭时取消所有排队 Future 并返回 503，在途任务等 120 秒（BR-60、BR-89） |
| 15 | 首请求触发加载，同时又有 8 个请求 | 第 9 个等待请求的判定含混 | 触发加载的首个请求算在途，其余按等待队列计数，满 8 后返回 429（BR-87） |
| 16 | 前端 180 秒放弃等待，服务端仍在合成 | 用户立即重试，新请求排在旧任务之后，可能进一步占满队列 | 前端如实提示结果未知，重复提交需二次确认；服务端不取消在途任务（BR-93、BR-96） |
| 17 | 临时目录无法安全创建或归属不明 | 克隆功能不可用，或误删非本程序文件 | 启动时校验归属，失败则禁用克隆并返回 503；清理只针对程序自有文件（BR-84） |
| 18 | 排队请求被取消或超时后，handler 的 `finally` 删除临时文件，与 worker 出队读取存在窗口 | 在途克隆请求读不到参考音频，被误报为 500 | 临时文件删除权唯一归 worker；handler 只在确认请求未出队后删除，判断与出队在同一临界区完成（BR-97） |

### 6.1 性能

性能验收必须同时看两侧指标：MLX 侧说明框架缓存是否清空，进程 RSS 说明内存是否还给系统。只看前者不能证明内存已回收。

| 指标 | 测量口径 | 通过条件 |
| --- | --- | --- |
| 模型加载耗时 | 直接测量加载函数开始到权重可用于推理的结束时间，不依赖 `/health` 轮询；连续 5 次冷启动 | M4 Pro 24GB 上 P50 ≤ 30 秒、5/5 成功。这是产品预算，首次实测后按实际值复核，若放宽必须在本文写明理由 |
| 冷启动首请求耗时 | 重启进程后，客户端发出 20 字中文请求到完整音频返回，包含加载、推理和编码；连续 5 轮 | 单独记录 P50/P95，不参与热启动统计，不与模型加载耗时混为一个指标 |
| 热启动首请求耗时 | 权重已在内存、`state=ready`，20 字中文，默认参数，请求到完整音频返回；连续 5 轮 | P50/P95 记录，P95 ≤ 8 秒 |
| 实时率 RTF | 40 字中文（约 10 秒音频），默认参数，预热 1 次后连续 5 轮 | P50/P95 记录；M4 Pro 24GB 上 P50 ≤ 1.0 |
| 峰值内存 | 合成期间 1 Hz 采样，同时记录进程 RSS 和 MLX `active`/`cache` | 记录绝对值并与权重文件大小对照，不得低于权重文件大小 |
| 卸载后 MLX 内存 | 卸载完成 0/5/30/60 秒各记录 `mx.get_active_memory()` 与 `mx.get_cache_memory()` | 相对加载前基线的增量 ≤ 峰值增量的 10% |
| 卸载后进程 RSS | 卸载完成 0/5/30/60 秒各记录一次进程 RSS | 60 秒时 ≤ 基线 + max(200MB, 峰值增量 × 20%) |
| 重载成功率 | 卸载后连续 5 次请求 | 5/5 成功 |
| 并发稳定性 | 20 个并发的 20 字中文请求 | 恰好 9 个被接受（1 在途 + 8 等待）且全部成功、无崩溃、无串线；恰好 11 个返回 429，`Retry-After` 均为 5 秒 |
| 排队超时 | 占满队列后等待超过 `MING_TTS_QUEUE_TIMEOUT` | 超时请求返回 429 并带 `Retry-After`，不重复处理 |
| 克隆可用性 | 10 段 5~30 秒参考音频，覆盖中英文 | 10/10 产出可播放音频，人工确认音色可辨 |
| 质量抽检 | 50 条文本，双人独立评分，细则见 §6.1.2 | 四项平均 ≥ 4.0，单项平均 ≥ 3.5，低于 3 分的样本不超过 5 条 |

> 表中的「M4 Pro 24GB」是性能验收基准机，不是功能支持范围。其他 Apple Silicon 机型只保证功能可运行，性能数据记录在 `docs/benchmarks.md`，未实测机型不作性能承诺（见 §6.2）。
>
> 模型加载耗时、冷启动首请求耗时、热启动首请求耗时是三个独立指标，不能互相替代：前者定位加载瓶颈，后两者定位推理和编码开销。

**内存验收的基线定义**

- 基线：进程启动、加载 tokenizer 完成、连续空闲 60 秒后的 RSS，以及此时的 MLX `active`/`cache`。
- 峰值：一次完整合成期间按 1 Hz 采样的最大值。
- 峰值增量：`max(0, 峰值 − 基线)`。峰值为 0 或低于基线时，只按绝对增量判定，即 MLX 增量 ≤ 100MB、RSS ≤ 基线 + 200MB。
- 观测窗口：卸载完成后 0、5、30、60 秒各一次；60 秒为判定点，其余为观察点。
- 三个结论分开写：权重引用是否释放、MLX 缓存是否清空、进程 RSS 是否回落。任一项不达标都算验收不通过，不得用另一项替代。

#### 6.1.2 质量评分

- 样本构成：中文 20 条、英文 15 条、德/西/法/韩/日各 3 条，共 50 条；覆盖短句、长句、数字（写成文字）、中英混排。
- 评分项：可懂度、自然度、音色一致性、指令遵循，各 1~5 分。

**OpenAI Audio Speech 非流式兼容子集**

兼容目标不是「完整兼容 OpenAI」，而是「非流式兼容子集」。矩阵外的行为不承诺兼容（BR-80）。

| 字段或行为 | OpenAI 语义 | 本服务行为 | 差异与验收 |
| --- | --- | --- | --- |
| `POST /v1/audio/speech` | 合成语音 | 相同路径和方法 | 兼容 |
| `model` | 指定模型 | 接受任意非空字符串，实际只服务 `Ming-3.0-tts` | 不校验取值，不因未知模型返回 400 |
| `input` | 待合成文本 | 1~1000 个 Unicode 码点 | 超出返回 400；上限是临时值，见 BR-94 |
| `voice` | 音色 ID | `auto`、`design` 或 Ming 内置音色名 | OpenAI 默认音色名（`alloy`、`echo` 等）返回 400，不静默回退 |
| `instructions` | 风格指令 | ≤500 字符，映射到 FREEFORM、VOICE_DESIGN、IP | 与情绪、属性、内置音色组合时返回 400 |
| `response_format` | `mp3`、`opus`、`aac`、`flac`、`wav`、`pcm` | 只支持 `wav`、`pcm`，默认 `wav` | 其他值返回 400；SDK 版本间默认值不一致（实测 `openai==1.109.1` 未显式传时会省略该字段，服务端按默认 `wav` 处理），调用方应显式指定 |
| `speed` | 0.25~4.0 | 0.5~2.0，映射到属性控制（待 Spike） | 越界返回 400；Spike 前标注实验状态 |
| `stream` | 流式返回 | 不支持 | `stream=true` 返回 400，说明「v1 暂不支持流式音频」 |
| 未知字段 | 通常忽略 | 同样忽略，不报错 | 只有已定义字段会校验；「未知字段忽略」与「未知 `voice` 报错」不冲突，后者是已定义字段的枚举校验 |
| 鉴权 | `Authorization: Bearer` | 不校验 | SDK 传任意 `api_key` 即可 |
| `usage` | 有 | 不返回 | 响应是纯二进制，不是 JSON |
| 响应 `Content-Type` | `audio/mpeg` 等 | `audio/wav` 或 `audio/pcm` | 与 `response_format` 一致 |
| 响应 `Content-Disposition` | `attachment; filename="speech.mp3"` | `attachment; filename="speech-<request_id>.wav"` 或 `.pcm` | 扩展名随 `response_format` 变化（BR-42） |
| PCM 元信息 | 不提供 | 额外返回 `X-Audio-Sample-Rate: 44100`、`X-Audio-Bits: 16`、`X-Audio-Channels: 1`、`X-Audio-Byte-Order: little` | 属于扩展头，OpenAI 无对应字段；裸 PCM 必须靠这些头判断格式 |

**SDK 验收方式**

- 使用 `client.audio.speech.create(model="Ming-3.0-tts", voice="auto", input="...", response_format="wav")`，把返回内容写成文件并用播放器打开。
- README 和 `docs/api.md` 必须给出这段示例，并注明 `voice`、`response_format` 应显式传入，`api_key` 可填任意非空值；不同 SDK 版本对 `response_format` 的默认处理不一致，显式传值才不会随版本变化。
- 只验证 HTTP 路径不算通过，必须以 SDK 实际调用成功为准（BR-81）。

### 6.3 安全与隐私

**监听与访问控制**

- 默认只监听 `127.0.0.1`。
- 指定非回环 `--host` 时必须同时设置 `MING_TTS_ALLOW_REMOTE=1`，否则启动失败并说明原因（BR-86）；不能只用启动日志提示代替门禁。
- 默认不启用 CORS，不返回 `Access-Control-Allow-Origin`；需要跨源时由使用方自行加反向代理。
- 校验 `Host` 头，只接受 `127.0.0.1`、`localhost` 和配置的监听地址，防止 DNS rebinding；监听 `0.0.0.0` 时，`0.0.0.0` 本身不是合法 Host 值，此时只接受回环地址与本机局域网 IP，不把通配地址当作放行依据。
- v1 没有鉴权，开放到局域网等于把合成能力和参考音频上传接口暴露给同网段，README 必须写明这一点。

**参考音频**

- 准确定位是「不持久化」：处理期间存在于内存和临时文件，请求结束立即删除，不写数据库、不写用户目录、不写日志。
- 临时目录默认 `<系统临时目录>/ming-tts`，以不跟随符号链接的方式创建并校验真实路径和所有者，权限 `0700`；文件权限 `0600`，每个请求独立文件。
- 清理只针对本程序命名的文件，不递归删除目录内容，不触碰目录之外的路径。
- 目录无法安全创建或无法确认归属时，禁用克隆功能，克隆请求返回 503；其他模式不受影响（BR-84）。
- 崩溃或强杀后的残留由下次启动清理（BR-85）。
- 不落任何原始音频到仓库、`models/` 或 `output/`。

**请求与日志**

- 请求体上限 20MB，超出返回 413，避免超大 base64 打满内存。
- 无论 INFO 还是 DEBUG，都不得记录合成文本、参考音频、参考文本、base64 音频和完整请求体；DEBUG 只增加耗时、任务模式、参数名等诊断信息（BR-62）。
- 不采集遥测，不调用外部服务；安装完成后运行期无外发请求。
- Web UI 不引用 CDN、外部字体或第三方脚本。
- 权重只从锁定来源下载，安装时校验不可变 revision 与 SHA-256，依赖版本锁定，避免供应链漂移；本地计算的校验和只证明完整性，不证明来源可信（BR-90）。
- 安装后保留 `LICENSE`，README 注明模型许可证和来源，不再分发权重。
- 声音克隆必须提示授权责任：UI 要求勾选确认，API 文档说明调用方需确保拥有声音使用权，服务端不做身份核验。
- Web UI 不持久化文本、参考音频和生成音频，刷新即清空。

### 6.4 可靠性

- 单个请求失败不影响进程，后续请求可继续。
- 模型加载失败后返回 503，允许重试，不需要重启进程。
- 健康检查不触发模型加载，不阻塞合成。
- 收到 SIGTERM 后停止接新请求，等待队列中的请求返回 503，取消其 Future，在途任务最多等 120 秒。
- 崩溃后不自动重启，由用户或外部进程管理器决定。
- 停止头偶发不触发导致的尾部低电平噪声不作为服务错误，文档给出换 seed 重试的说明。
- 合成结果为空时返回 500，不返回 0 字节音频。
- v1 不设生成超时，只受排队超时和关闭等待约束（BR-96）。

**A-6 任务模式矩阵（唯一权威定义）**

本节是任务模式的唯一权威定义。§3.4、UC-05、§4.3、§6.2、A-4 和 BR-31~BR-38 只引用本表，不再各自维护字段规则（BR-74）。修改任务规则必须先改本表。

任务模式取值：`auto`、`tts`、`freeform`、`voice_design`、`multilingual`、`basic`、`emotion`、`dialect`、`ip`。API 的 `task` 字段用小写；响应头 `X-Resolved-Task` 用模型侧大写名称（`TTS`、`FREEFORM`、`VOICE_DESIGN`、`MULTILINGUAL`、`BASIC`、`EMOTION`、`DIALECT`、`IP`）。`auto` 只是请求值，不会作为解析结果返回。

「控制项」定义：`instructions` 非空、`emotion` 非空、`speed`≠1.0、`pitch`≠0、`volume`≠1.0、`voice`≠`auto`、`reference_audio` 存在、`language` 为方言或 `de/es/fr/ko/ja`。`model`、`input`、`response_format`、`seed`、`cfg`、`sigma` 不算控制项；`language=auto/zh/en` 视为未设置。

> 本表及 UC-05 中「`language` 七种任一」统一指 `language`∈{`auto`、`zh`、`en`、`de`、`es`、`fr`、`ko`、`ja`}，即除两种方言外的全部取值（含 `auto` 与中英）。

| task | 模型侧任务 | `auto` 触发条件 | 必填 | 允许（可选） | 禁止（400） |
| --- | --- | --- | --- | --- | --- |
| `tts` | TTS | 有 `reference_audio`；或 `voice` 为内置音色且无情绪/属性/指令/方言 | `input`；克隆时 `reference_text` | `language` 七种任一、`seed`、`response_format` | 内置音色与 `reference_audio` 同时出现、`voice=design`、`instructions`、`emotion`、属性非默认、方言语言 |
| `freeform` | FREEFORM | `instructions` 存在，且无音色、参考音频、情绪、属性、方言 | `instructions` | `input`、`language` 七种任一、`seed`；**显式指定时**允许 `reference_audio` + `reference_text` | 内置音色、`voice=design`、`emotion`、属性非默认、方言语言 |
| `voice_design` | VOICE_DESIGN | `voice=design` | `instructions` | `input`、`language` 七种任一、`seed` | `reference_audio`/`reference_text`、内置音色、`emotion`、属性非默认、方言语言 |
| `multilingual` | MULTILINGUAL | `language` 为 de/es/fr/ko/ja，且无音色、指令、情绪、属性 | `language` | `input`、内置音色、`seed` | `instructions`、`emotion`、属性非默认、方言语言、`reference_audio`、`voice=design` |
| `basic` | BASIC | 无任何控制项 | `input` | `model`、`response_format`、`seed`、`language`∈{auto, zh, en}、`voice=auto` | `voice`≠`auto`、`instructions`、`emotion`、属性非默认、参考音频、方言语言、`language` 为 de/es/fr/ko/ja |
| `emotion` | EMOTION | `emotion` 或属性非默认，且无指令、方言、参考音频 | `emotion` 或至少一项属性非默认 | `input`、内置音色、`language` 七种任一、`seed` | `instructions`、方言语言、`reference_audio`、`voice=design` |
| `dialect` | DIALECT | `language` 为 sichuanese/cantonese，且无指令、情绪、属性、参考音频 | `language` | `input`、内置音色、`seed` | `instructions`、`emotion`、属性非默认、`reference_audio`、`voice=design`；不得向模型传 language ID |
| `ip` | IP | 仅显式 `task=ip` | `instructions` | `input`、`language` 七种任一、`seed` | `reference_audio`、内置音色、`emotion`、属性非默认、方言语言 |

**`auto` 解析顺序**（§4.3 是同一规则的流程图版本）

1. 有 `reference_audio` → `tts`（克隆）
2. `voice=design` → `voice_design`
3. `language` 为四川话/粤语 → `dialect`
4. 有 `emotion` 或属性非默认 → `emotion`（可带 5 种语言 ID）
5. 有 `instructions` → `freeform`（可带 5 种语言 ID）
6. `voice` 为内置音色 → `tts`（内置音色）
7. `language` 为 de/es/fr/ko/ja → `multilingual`
8. 其他 → `basic`

解析前先做 §4.3 的七项冲突检查，命中任一直接 400。`freeform` 带参考音频只能显式指定，`auto` 永远不会推断出这一组合。

`emotion` 为自由字符串，建议值：中性、高兴、悲伤、愤怒、惊讶、恐惧、厌恶、温柔、严肃。服务端不校验具体词，原样传给模型侧指令；情绪能力当前处于「待 Spike」状态（§1.7），模型不识别时不会报错，只按默认语气合成，`docs/api.md` 必须标注这一点。

**属性控制与任务解析的联动**：`speed`/`pitch`/`volume` 当前处于「待 Spike」状态（§1.7）。本表中依赖「属性非默认」的触发条件（如 `EMOTION` 的 auto 触发第 4 步）以该能力通过 Spike 为前提；若 Spike 判定属性控制不支持，非默认属性值按 §1.7 映射返回 400，相关触发条件随之失效，本表与 §1.7、§4.3 必须同步修订（BR-83），不允许出现「矩阵仍把属性当控制项、§1.7 已判不支持」的中间态。

## 8. 业务规则汇总

| 编号 | 规则 |
| --- | --- |
| BR-01 | 环境固定放在 `envs/ming-tts`，权重固定放在 `models/ming-tts/8bit`，两者都不入库 |
| BR-02 | 安装脚本必须幂等，已存在的环境和权重不重复创建或下载 |
| BR-03 | 运行时使用 Python 3.11，依赖以 `runtimes/ming_tts/requirements.txt` 为准，必须固定完整解析结果而不是只写顶层包；mlx-audio 必须固定到包含 PR #1047 的提交，0.6.0 及更早版本禁止使用，安装和启动时都要校验；完整锁定规则见 BR-91。2026-10-21 实测：PR #1047 已合入 main（merge commit `3530c33a5f5412dfbd1ea70fece3d867b4860c0a`），PyPI `0.6.1` 是首个包含该 PR 的发行版，现固定 `mlx-audio==0.6.1`，结论见 `docs/benchmarks.md` |
| BR-04 | 权重默认从 ModelScope 的 `bujidc/mlx-community_Ming-3.0-tts-0.5B-8bit` 下载，下载时记录来源和 revision；Hugging Face 的 `mlx-community/Ming-3.0-tts-0.5B-8bit` 作为备用来源；安装后运行期不得联网 |
| BR-05 | 安装完成前必须校验 `config.json`、`model.safetensors`（或分片加 `model.safetensors.index.json`）、`tokenizer.json`、`tokenizer_config.json`、`vocab.json`、`merges.txt`、`special_tokens_map.json`、`added_tokens.json`、`LICENSE` 和 `.revision`，缺失则非零退出；`campplus.safetensors` 缺失只警告，`configuration.json`、`README.md`、`.gitattributes` 不参与校验 |
| BR-06 | 卸载只删除 `envs/ming-tts` 和 `models/ming-tts/8bit`，不修改系统 Python |
| BR-07 | CLI 参数为 `--text`、`--output`、`--voice`、`--language`、`--task`、`--ref-audio`、`--ref-text`、`--instruct`、`--emotion`、`--speed`、`--pitch`、`--volume`、`--seed`、`--format` |
| BR-08 | CLI 默认输出到 `output/ming-tts-<时间戳>.wav`，扩展名随 `--format` 变化；标准输出只打印输出文件绝对路径，日志走标准错误，音频不写标准输出；`--format` 未指定时按 `--output` 扩展名推断，扩展名与格式冲突时退出码 2 |
| BR-09 | CLI 和 API 共用同一套请求校验、任务解析和合成逻辑，不允许两套实现 |
| BR-10 | CLI 退出码为 0 成功、2 参数错误、1 运行错误 |
| BR-11 | CLI 是一次性进程，完成后退出并释放模型内存 |
| BR-12 | 服务通过 `scripts/start_ming_tts.sh` 启动，底层是 `runtimes.ming_tts.app:create_app` 的 uvicorn factory；脚本只做环境、版本和端口检查，不复制业务逻辑；权重路径启动时固定，修改需重启 |
| BR-13 | 只允许单 worker，禁止 `--workers` 大于 1 |
| BR-14 | 服务启动时只加载配置和 tokenizer，不加载权重，`/health` 立即可用 |
| BR-15 | 端口被占用时启动失败并明确报错，不自动换端口 |
| BR-16 | 默认监听 `127.0.0.1`；开放局域网必须满足 BR-86 的远程访问门禁（非回环 host 且设置 `MING_TTS_ALLOW_REMOTE=1`，否则启动失败），通过门禁后才在启动日志提示无鉴权风险 |
| BR-17 | `input` 必填，去除首尾空白后长度按 Unicode 码点计数，范围 1~1000；为空或超限返回 400，不做截断 |
| BR-18 | 请求体上限 20MB，超出返回 413 且不解析正文；上限不提供环境变量放开 |
| BR-19 | `response_format` 只接受 `wav` 和 `pcm`，默认 `wav`，其他值返回 400 |
| BR-20 | `speed` 范围 0.5~2.0，默认 1.0；`pitch` 范围 -12~12，默认 0；`volume` 范围 0.5~2.0，默认 1.0；越界返回 400，不做截断 |
| BR-21 | `language` 只接受附录 A-5 的取值，未知值返回 400 |
| BR-22 | `voice` 默认 `auto`，可接受 `design` 或内置音色名；未知内置音色返回 400，不静默回退到默认音色，错误文案必须回显用户输入的音色名并列出当前已知的有效音色；模型侧无法提前枚举音色时，只把可识别的未知音色异常映射为 400，其余加载或推理异常按 500/503 处理，不得把内部故障报成参数错误 |
| BR-23 | `reference_audio` 和 `reference_text` 必须成对出现，只给一个返回 400 |
| BR-24 | 参考音频只接受 WAV/FLAC，时长 5~30 秒，解码后不超过 10MB，采样率 16k~48kHz，单声道或双声道；不合格返回 400 |
| BR-25 | `instructions` 不超过 500 字符；`task=voice_design` 和 `task=ip` 时必须提供 |
| BR-26 | `seed` 范围 0~2147483647，默认由服务随机生成；实际使用的 seed 通过 `X-Seed` 返回 |

## 9. 易用性设计原则

### 9.1 零配置开始

用户只需要一条命令完成安装，第二条命令生成第一段语音。模型路径、端口、空闲阈值、输出目录都有默认值，不要求先读文档。Web UI 打开后默认就是「内置音色」页，输入文本即可生成。

### 9.2 用户可见配置不超过 4 项

| 配置 | 是否常驻界面 | 说明 |
| --- | --- | --- |
| 文本 | 是 | 每次合成都需要 |
| 模式 | 是 | 内置音色、克隆、声音设计三选一 |
| 语言 | 是 | 默认自动，覆盖大多数场景 |
| 音色或声音描述 | 是 | 随模式变化 |
| 情绪、语速、音高、音量 | 否，高级设置折叠 | 默认值覆盖大多数场景 |
| CFG scale、Sigma | 否，高级设置折叠 | 默认 2.0 / 0.25，与官方一致，通常不需要改 |
| 参考音频与转录 | 否，仅克隆页 | 克隆时必填 |
| 空闲阈值、端口、队列上限 | 否，环境变量或启动参数 | 部署时设定一次 |

### 9.3 不主动打扰

- 不在页面弹订阅、评分、更新提示。
- 模型加载和卸载只在状态徽标上体现，不弹窗。
- 错误只展示一条可行动的信息，不堆叠技术细节。
- 长文本合成不伪造进度百分比，只显示「合成中」和已等待时间。

### 9.4 小白语言规范

| 内部说法 | 面向用户说法 |
